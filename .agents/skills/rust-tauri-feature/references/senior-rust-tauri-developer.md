## 1. Architecture & Crate Boundaries

- **`crates/ide-*`** (backend domain crates):
  - One domain per crate. Share cross-domain types through `ide-core`; NEVER reach into another domain crate's internals.
  - Every public/command-facing error converts at the crate edge into `IdeError` and returns `IdeResult<T>`.
- **`crates/ide-host`** (shared project-host & remote RPC layer):
  - Put project-scoped and remotely-capable command implementations in `crates/ide-host/src/ops/<domain>.rs`.
  - Declare each command once on its implementation using `#[ide_command::command(trust = ...)]` (`always`, `outside_restricted`, or `trusted`), export it via `ide_command::domain!(<domain>: <fn1>, ...);`, and register the module in `ide_command::domains!(...)` in `crates/ide-host/src/ops/mod.rs`.
  - Tauri adapters, `openidea-server` RPC handlers, and `tauri-specta` bindings are derived automatically from `#[command]`.
- **`src-tauri/`** (desktop shell glue ONLY — NO domain logic):
  - `state.rs` (`AppState` / `Project`), `events.rs` (`IdeEvent`), and `commands/<domain>.rs`.
  - Desktop-only commands (windowing, native dialogs, OS integrations, or desktop bodies of `#[command(desktop_body = ...)]`) live in `src-tauri/src/commands/<domain>.rs` with `#[ide_command::desktop_command(trust = ...)]` and `ide_command::desktop_domain!(...)`, registered in `catalogue()` in `src-tauri/src/commands/mod.rs`.
  - Maintain parity with `routes_exactly_the_commands_a_server_of_this_build_declares` (if you add a `#[command]` domain in `ide-host`, register it in `src-tauri/src/commands/mod.rs` too).
- **`src/bindings.ts`**:
  - Generated by `pnpm gen:bindings`. NEVER edit `src/bindings.ts` by hand. Whenever IPC command signatures or exported types change, run `pnpm gen:bindings` and verify it compiles cleanly.

## 2. Rust, Async, IPC & Security Rules

- **IPC coordinates**: 0-based lines, **UTF-16** columns/offsets everywhere (`ide-core::text`). Never leak UTF-8 byte offsets across IPC.
- **Never block async/UI/Tauri command threads**:
  - Run disk I/O, parsing, process waits, or CPU-heavy work via `host.blocking(...)` / `tokio::task::spawn_blocking` / `rayon`.
  - Support cancellation for long operations using UI-allocated `RequestId` + `cancel_request` + `CancellationToken`.
- **Streaming & events**:
  - Stream command results with `ide_host::ops::Channel<T>` (derived to `tauri::ipc::Channel<T>`).
  - Push backend-to-UI notifications via `EventSink` (`IdeEvent`), scoped appropriately (per-window/per-project).
- **Trust & safety**:
  - Pick the tightest `TrustClass` (`trusted` for workspace execution/writes/tool invocation, `outside_restricted` when safe without an untrusted project, `always` only for benign global UI/env queries).
  - Canonicalize/validate paths against workspace roots where applicable. Never construct shell strings with untrusted input—pass argument arrays to `Command`.
  - Handle cross-platform behavior (Linux, macOS, Windows: path separators, `.exe`/`.cmd`, line endings).
  - Avoid `.unwrap()` / `.expect()` on untrusted or runtime-fallible data in production paths; propagate `IdeResult<T>`.

## 3. Frontend (`src/`) Rules

- **Feature isolation**:
  - Feature modules live in `src/features/<name>/` and export `activate()`, registered in `src/features/index.ts`.
  - Features NEVER import each other directly. Communicate through actions, `src/platform/` services/context keys, and `src/workbench/contributions.ts`.
  - Every user-invocable action has a stable action id; default shortcuts live in `src/platform/keymaps/`.
- **UI & Styling**:
  - Use primitives from `src/ui/` and inline SVG icons from `src/ui/icons.tsx` (never emoji).
  - Style exclusively with CSS Modules + design tokens from `src/styles/tokens.css` (no hex literals in components/styles; use `--space-*` tokens for `gap`).
  - Use real `<button>` and `<input>` elements; set `aria-label` on all icon-only buttons.
- **Localization**:
  - Put all user-visible text in BOTH `src/platform/locales/text/en.json` and `src/platform/locales/text/zh.json` (`textCatalog.test.ts` enforces parity).

## 4. Verification Before Reporting Done

Run scoped checks relevant to your changes (never chain multiple slow builds into a single command that might exceed timeouts):
1. If IPC types/commands changed: `pnpm gen:bindings`
2. Rust formatting & tests: `cargo fmt --all --check` and `cargo nextest run -p <affected-crate>` (plus `-p ide-host` / `-p openidea` if command catalogue changed)
3. Rust lints (once after edits stabilize): `cargo clippy -p <affected-crate> --all-targets -- -D warnings`
4. Frontend checks: `pnpm typecheck`, `pnpm lint`, `pnpm vitest run <affected-test-paths>` (note: do NOT pass `-- <path>` to `pnpm test`)

Report exact file paths, symbol names, commands run, and observed pass/fail outputs. Never claim verification you did not execute.
